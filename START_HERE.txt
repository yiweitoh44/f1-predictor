F1 PREDICTOR — OPENF1 DATA VERSION

SETUP
Keep predict_anytime.py, openf1_data.py, session_influence.py, grid_sources.py,
circuit_sections.py, forecast_validation.py, tracks.csv and requirements.txt together. Run only
predict_anytime.py; the others are imported helpers.

  python -m pip install -r requirements.txt
  python -m pip check

No FastF1 installation, F1 account, F1TV subscription, OpenAI key or GPU is
required. An existing FastF1 installation does not need to be uninstalled.
OpenF1's public completed-session data is used; its paid live service is not.
Keep old caches and uploaded archives: they are not read by this data version
and can remain available for v3 research.

COMMANDS
  python predict_anytime.py --year 2026 --list-races
  python predict_anytime.py --year 2026 --race Austin --session qualifying
  python predict_anytime.py --year 2026 --race Austin --session race
  python predict_anytime.py --year 2026 --race Austin --session sprint
  python predict_anytime.py --year 2026 --race Austin --session sprint-qualifying

Only choose Sprint/SQ at a Sprint weekend. Run from the f1-predictor Git folder.
After the scheduled target start, enter y to replay using the pre-start cutoff.
An explicit --as-of timestamp must precede the target and cannot be in the future.
The target's results and later sessions are never prediction inputs.
Before current practice exists the model uses earlier form. Rerun after practice
and qualifying to use newly available inputs. The first four weekends can use
a labelled evidence-only fallback; the trained model requires four earlier
usable weekends. Missing inputs are reported, not invented.

SOURCES AND CACHE
OpenF1 supplies meeting/session schedules, drivers, classifications, grids,
lap/sector times, stints, pit events, weather and race-control messages.
Cancelled meetings and testing are excluded from round numbering. Session and
meeting keys must match. Session starts/ends and all accepted lap timestamps
must precede the prediction cutoff. Recent practice/Sprint pace also requires an
observed chequered flag before cutoff; the original conservative 24-hour
fallback is retained for older sessions with missing status messages. Historical revisions can differ from
what was originally published: this is not an original-snapshot archive.

The published starting-grid policy remains FIA documents first, then dated or
observed F1/OpenF1 records, with qualifying order as fallback. Manual --grid and
--grid-source qualifying still work. These sources do not use FastF1.
FIA publication times in the repeated autumn Paris hour use the later UTC
instant, so a grid is never admitted using the earlier ambiguous interpretation.
Pit-lane starters retain the existing back-of-field scoring treatment; actual
exit order and delay are not modelled. Historical missing grid values remain
missing for the benchmark rather than being invented.

Raw OpenF1 responses are cached under ~/F1Data/cache/openf1/http. On Windows:
  C:\Users\Yi Wei Toh\F1Data\cache\openf1\http
The first cold run can take several minutes because it loads prior weekends.
Requests are spaced to respect OpenF1's free-tier limits and rate-limit
responses are retried. Downloads print their endpoint/session progress.
Metadata, empty responses and recent-session responses expire after 15 minutes.
Responses fetched at least 48 hours after session end can be reused for seven
days. Nonempty responses are not assumed complete. --refresh renews them sooner;
--offline preserves cached responses regardless of age. No old FastF1 summaries
are consumed.

--offline forbids all downloads, including grid sources. Required metadata must
already be cached. --refresh renews source responses and cannot be combined with
--offline. --rebuild-summaries is retained for command compatibility: processed
OpenF1 evidence is calculated from raw cached responses on each run anyway.
Failed or sparse sources are reported in run_info.json. Weather is diagnostic;
missing competitive-session weather is left unknown rather than filled.

LAP QUALITY
lap_quality.csv records accepted/rejected current-session laps and reasons.
These are derived checks, NOT an official IsAccurate flag from the provider.
Reject missing/nonfinite timing, duplicate lap identities, pit boundaries,
deleted laps, active flags/neutralisation, missing/conflicting stints and unknown
tyre information. Missing sectors are unverified, distinct from inconsistent sums. Sector sums must match lap duration within 3 milliseconds.
Deletion resolution uses the driver and lap stated in the message, or a unique
lap-time match. race_control.lap_number is the message's current race lap, not
necessarily the deleted lap; it is not used as a deletion target.
An unresolved notice leaves that driver's already-started laps unverified up to
the message time plus a one-second allowance for whole-second message timestamps
and lap-start jitter. Later laps can pass all normal checks. This is an explicit
clock allowance, not a guarantee of identical timestamps across sources. An
ambiguous reinstatement cannot validate multiple candidate laps. Pit-out durations
can include garage time before date_start, so start+duration is not treated as a
reliable outlap crossing time when resolving a deletion. Outlaps remain excluded.
Pit lap numbering can refer to entry or exit: use explicit outlap evidence to
exclude the entry/exit pair without also discarding an earlier clean lap. Unknown
pit conventions stay conservative; future pit reports are not used.
The quality_state column separates valid_for_pace, excluded_from_pace and
unverified. Unknown evidence is not described as proven invalid.

The experimental strict policy also checked consecutive lap-start timestamps.
It is NOT the default: OpenF1 timestamps did not support a 3-ms continuity test
in our data. On 23 matched historical sessions, this reduced accepted laps from
7,515 to 563. Tightening sector sums alone from 50 ms to 3 ms did not remove any
of those 7,515 laps. Timing continuity cannot be claimed verified by the default.
Do not reinterpret a failed precision check as proof every lap time is wrong.

MODEL POLICY
Native XGBoost uses six Q/SQ or seven Race/Sprint evidence inputs by default.
GP qualifying after a loaded practice session, without completed SQ/Sprint
evidence, uses 22 inputs: the original six plus per-session pace/gaps, availability,
support, comparison-field sizes and the Q/SQ training-format flag. It uses tree
depth three. SQ after FP1 uses the dedicated 43-input model described below,
also at depth three; the other models retain depth two. Scores/gaps retain
monotonic constraints; support/context is not forced to imply speed direction.
Except for trained SQ after FP1, scores combine 85% explicit evidence with 15%
learned adjustment. The early fallback has no learned component. History covers
four earlier rounds with a three-round half-life. Earlier/later sessions are
selected in scheduled order; each training example uses only its earlier inputs.
The explicit history score gives GP/Q three times the vote of S/SQ within one
weekend. Training also retains one total budget per weekend; trained SQ after
FP1 separately favours SQ rows inside that budget, as described below.

Explicit anchor source budgets when available (not fitted feature importance):
  Race: history .20, grid/Q .65, Sprint .10, earlier SQ .025, practice .025.
  Sprint: history .20, grid/SQ .75, practice .05.
  Qualifying: history .30, Sprint .10, earlier SQ .50, practice .10.
  SQ: history .85, practice .15.
Race/Sprint split the existing grid budget equally between starting position and
qualifying performance when both are available. Missing sources redistribute
weights. No driver-specific bonuses or weather/upgrade bonuses are introduced.
Pace support, the 0..5% gap guard, history/circuit groups, monotonic constraints,
random seed and simulation policy are retained. SQ after FP1 alone admits older
validated tyres within the same matching bands; other formats keep age <=5 for
short-run practice. No other format's learned score or matching changes.
Section telemetry remains disabled and excluded from every fit.

ROSTER
Prefer completed current-weekend competitive entries. Otherwise a full FP2/FP3
lineup is assumed to be entered; FP1 reserves do not replace the last competitive
entry list. Incomplete later practice keeps the previous competitive roster.
Without a current competitive/full later-practice list, driver/team continuity
is an assumption. Use --roster for confirmed replacements, especially before SQ.
A manual CSV has driver,team and optional name columns. No later target-session
entry list is fetched to resolve a pre-session uncertainty. run_info.json records
the prediction entrants, roster basis and practice-only drivers.

Remaining source limits: some OpenF1 tyre ages/freshness disagree with the saved
FastF1 sample; age==0 is a freshness proxy, not FastF1's explicit New field.
Some stints/sectors are absent. Practice phase uses elapsed scheduled-session
time, unlike FastF1's feed-relative clock. Exact phase/tyre parity is unverified;
missing fields are not invented or checks weakened to favour a known result.

V3 DATA AUDIT AND REPRODUCIBILITY
The v2 tag preserves the FastF1-based version. OpenF1 supplies this branch's
session data; FIA/F1/OpenF1 published-grid selection remains separate.

Every downloaded or reused OpenF1 response is saved in a content-addressed
snapshot under ~/F1Data/cache/openf1/snapshots. source_manifest.json beside the
prediction identifies the URL, download time, record count, snapshot path and
SHA-256 for each response used. A refresh preserves the previous response before
replacing the active cache. Snapshots consume disk space as sources change;
keep them when preserving a prediction. They are never uploaded to Git.
Existing responses only establish their recorded fetch time. We cannot recreate
an original pre-race publication from a newer historical download. The snapshot
archive does not automatically choose old responses for --as-of runs.

--offline uses the active local response cache and forbids downloads:
  python predict_anytime.py --year 2026 --race Singapore --session race --offline
It requires previously downloaded OpenF1 sessions and metadata; a FastF1 cache
alone is insufficient. Keep the entire cache/openf1 directory when moving it.

lap_quality.csv also shows the reported stint, initial tyre age, derived tyre
life, freshness assumption and elapsed seconds from scheduled session start.
data_coverage.csv reports raw/accepted/unverified lap counts and drivers with
usable short/long pace for current and historical inputs. Zero laps for Q/R
means this version uses classifications there, not that the race had no laps.

KNOWN SOURCE LIMITS
OpenF1's stint parser takes the first available TimingAppData TotalLaps value
as tyre_age_at_start. It does not expose that feed's explicit new/used tyre flag.
Our age==0 freshness grouping is a proxy, not verified FastF1 FreshTyre parity.
Missing/conflicting stints remain unknown; we do not invent tyre ages.
OpenF1 can infer a missing lap duration from its sectors. A matching sector sum
therefore establishes internal consistency, not independent timing verification.
Its lap starts are message timestamps and do not support a universal 3-ms
consecutive-lap test. Accepted means passed our derived checks, not guaranteed
fuel/traffic/engine-mode equivalence. Those programmes are unknown in FastF1 too.
Upstream code examined:
  https://github.com/br-g/openf1/tree/87540e3f495bbd9bedb37b10456dd848c8f193d6/src/openf1/services/ingestor_livetiming/core/processing/collections

Practice phases use ten-minute bins from scheduled start. FastF1 uses a different
feed-relative origin. The available raw comparison sample is Hungary RACE:
its feed origin is 3049.658 seconds before scheduled start. That does not establish
a practice-session offset. Race/Sprint comparisons use lap-number bins, so this
clock difference does not change those bins. No arbitrary clock correction is
applied to practice. Fuel correction and section telemetry remain disabled.

TYRE VALIDATION AND LOCAL CACHE RECOVERY
If a lap feed contains a driver number missing from that session's driver list,
those laps stay unverified with reason "missing driver identity" in lap_quality.csv.
The loader warns with the affected numbers and retains other drivers' validated
laps. It does not guess an identity or use a later session to fill the entry.
If no validated laps remain, practice remains unavailable.

Empty lap, stint or race-control feeds cannot validate pace. When an empty pit
feed conflicts with observed later pit exits, keep checked interior laps using
explicit non-outlap flags and an observed next lap in the same valid stint.
Outlaps and their preceding inlaps remain excluded. Missing flags, ambiguous
continuations and unconfirmed stint tails stay unverified, one lap at a time.
Later observations beyond the cutoff cannot validate earlier laps.
The terminal, run_info.json/source_warnings and lap_quality.csv report the gap
and the evidence used. Other drivers' usable laps are retained; practice is
unavailable if no validated laps remain or an essential feed is absent.
Sprint classifications can remain usable even without pace; existing completion
and roster checks still apply. Empty weather is diagnostic only. The latest response stays
cached and old populated responses are not silently substituted. Nonempty feeds
are not automatically proof of completeness.
Retry later with --refresh if the provider has repaired the feed. --offline
keeps the cached response; it does not repair the missing feed. Only individually
checked laps can supply pace while the gap persists; check coverage.

Tyre ages must be finite nonnegative whole lap counts. Boolean/fractional ages,
invalid stint numbers, reversed/malformed bounds and overlapping stints cannot
validate pace. Such evidence stays unverified rather than being guessed. A broken
record for one driver does not discard other drivers' usable laps. Unrelated
future incomplete stints do not erase an otherwise valid current match.
lap_quality.csv now includes tyre_evidence_issue alongside the age/freshness
assumptions. This does not reconstruct FastF1's explicit new/used tyre field.

Missing, unreadable or wrong-session active OpenF1 responses can be restored
from local snapshots. Recovery verifies the saved SHA-256, exact query URL,
session identity and response structure before writing the active copy. A small
index makes recovery faster; older snapshots without that index can be scanned.
Recovery retains the original fetched time: online freshness/--refresh rules
still apply. Failed online downloads do not automatically switch to stale data.
Use --offline when intentionally working from saved responses during an outage.
Recovery is reported in the terminal and source_manifest.json/cache_recoveries.

Back up the entire ~/F1Data/cache/openf1 folder, including http, snapshots and
index, outside Git. Existing caches work unchanged; no redownload is required.
A snapshot cannot reconstruct a session that was never downloaded, and no new
independent practice-data provider is enabled by this update.

EARLY-SEASON FORECASTS
For rounds 1–4, when four earlier usable weekends do not exist, the predictor
uses the existing explicit evidence score without fitting an ML adjustment.
It uses available current-season form, practice and Q/grid information; it does
not load a prior season or the target result. No new source weights are tuned.
Missing history has the existing neutral value, not an invented prior result.

Fallback output is explicitly labelled. model.json contains its evidence policy,
not an XGBoost booster; run_info.json records forecast_method, zero trained
examples and zero backtests. Sigma 0.20 is a fixed uncalibrated simulation-spread
assumption in normalized score units, not measured error or a real probability.
The eight-test native-model checks remain unchanged; fallback forecasts are
scored separately. After the warm-up, the established native model is retained.
Missing later-season history does not silently activate early-season mode.

Before any competitive roster exists, a full FP2/FP3 lineup can be assumed;
FP1 alone cannot silently promote reserve drivers. Use --roster to confirm the
entrants when needed. With no usable distinguishing evidence, the run stops
rather than presenting a random ranking. Before the first practice of the year,
a roster alone therefore cannot create a meaningful forecast.

SAVING AND CHECKING A FORECAST
Each normal run still writes latest. It also saves a separate forecast copy:
  ~/F1Data/outputs/<year>_<round>_<session>/forecasts/<timestamp>_<id>
The printed path identifies the copy. It preserves predictions, model, effective
inputs/policy, starting grid, backtests, run metadata and source manifest, with
file hashes, code/default-input hashes and runtime versions. Copies consume disk
space but omit the large training table and raw cache. Repeated runs do not
replace these copies. Keep them outside Git with your existing raw-data archive.

After the session, prepare an actual-results CSV with these columns:
  year,round,session,driver,position
Use original published positions and driver codes; do not renumber a subset.
Session accepts Q, SQ, S, R or the normal command's session name. Include only
one event/session and at least three identified drivers. Then run:
  python predict_anytime.py --score-forecast "<printed forecast-copy path>" --actual-results "results.csv"
No --race argument or download is required for this scoring operation.

Scoring verifies the saved files and event/session identity, and waits until the
recorded scheduled end. The input cutoff cannot be after forecast creation or
the target start. A copy created after the target start remains labelled
historical replay even if --as-of was before the target. A copy created before
the saved scheduled start is labelled pre-session; that timestamp is not a
claim that the model choice was never informed by earlier experiments.

The score compares the actual published pole/winner and top-three identities.
Missing P1 is rejected, not promoted from P2. If top-three positions are missing,
that comparison is omitted. Full ranking error needs matching driver fields and
complete position orders; exclusions are explicit, with no silent intersection
or renumbering. Results go into a separate evaluations directory with forecast,
actual-data and scorer hashes; saved forecasts are left unchanged.

This provides the tooling for future validation; no future job is scheduled and
future weekends still need to happen. Actual outcomes are supplied only to the
separate scoring command and never enter the forecast through that command.

EXPANDED QUALIFYING AND LAP-MATCHING REVIEW (4 NOVEMBER 2026)
The initial reviews tested 18 qualifying settings and ten lap-matching settings.
Those trials retained scoring and added an evidence audit. The broader review
below supersedes their completion statements and adds an active qualifying model
input improvement. Existing lap matching is retained.

The expanded review covered all identified feasible method families within these
two items, with representative settings and joint checks:
  - Session recency, equal/latest/selected practice sessions and stronger FP3 weight.
  - Mean/median/best admitted comparisons; soft preference/soft-only/compound priority.
  - Support/coverage weighting and history/practice shares from zero to 100%.
  - Driver/team history composition within the same current-season window.
  - Separate native practice inputs, missing-value handling, learned shares and
    tree capacity; robust losses, ranking, pole classification and residual learning.
  - Fixed/overlapping windows, direct nearest-time pairs, mutual/one-to-one pairs,
    connected pairwise fits, robust reference/cohort statistics and fallback rules.
  - Start/midpoint timing, exact/near tyre ages and sensitivity to the derived
    fresh/used proxy; raw missing-tyre/timing checks were never weakened.
  - Joint tests of matching and input treatments, including discovery-selected
    candidates. No driver-specific or known-winner exceptions.

There were 139 settings including baseline controls: 62 input settings, 35 direct/
robust matching settings, 13 learning-target settings, six freshness-proxy checks
and 23 joint settings. Across 5,580 recorded forecast attempts, eight attempts
could not distinguish drivers early in the year; those failures count against the
candidate, rather than being dropped. Repeated stages are not independent races.
Earlier trial reports and all experimental code remain outside Git.

The selected treatment keeps existing explicit scores and adds each practice
session's admitted rank, normalized matched gap, availability, matched support
and mean comparison-field size to the native model. Unknown scores/gaps remain
NaN and use native missing-value handling, not history imputation. A Q/SQ flag
separates the pooled historical formats. It won the discovery comparison and
passed the same checks on later rounds; no candidate was rescued by one known
winner. The original two-lap/four-driver admission rules and lap matching remain.

Source budgets, history window, simulation seed, source/grid selection and main
prediction tables are unchanged. This activates only for GP qualifying after
practice with no completed SQ/Sprint evidence. Early-season evidence-only fallback,
before-practice forecasts and all other requested formats retain their policies.
No new command, dependency or additional API endpoint is required.

Practice fields in prediction_inputs.csv and Q/SQ rows of training.csv:
  qual_FP#_score: admitted normalized comparison rank; lower is better.
  qual_FP#_matched_gap_pct: mean admitted compound gap; not an estimated Q lap.
  qual_FP#_gap_norm: that gap divided by the existing 5% comparable-gap limit.
  qual_FP#_available: 1 when this driver has an admitted comparison, otherwise 0.

SIMULATION UNCERTAINTY — FINAL-SCOPE ITEM 6, EXPANDED REVIEW

This expanded review supersedes the initial retained-policy conclusion. The
broader literature/reasoning review found limitations in the old experiment:
finite simulation ordering jitter was sometimes used to reject probability laws,
and sampled likelihood floors could hide the severity of rare wrong predictions.
The review now separates numerical integration from the probability model.

WHAT IS ACTIVE
1. Exact mean positions. For any driver, expected rank is one plus the sum of
   probabilities that each other driver finishes ahead. Those pair probabilities
   have direct formulas for the supported noise laws. No extra package is needed.
   Changing --simulations cannot shuffle the predicted order. Winner/top-three
   shares and close-call estimates still come from the same coherent joint draws.
   Very close sampled shares can fluctuate around the fixed expected order.
2. Trained Race/Sprint base forecasts use Gumbel score noise, with scale sigma*sqrt(6)/pi
   so its standard deviation matches the existing error-based sigma. No new
   fitting weight or driver-specific rule is added. Q/SQ and fixed early-season
   fallback retain Gaussian noise. Sigma remains the latest-four-window base
   residual standard deviation, floor .03; early sigma remains .20. Eligible
   Sprints now replace the final noise/mean with the joint residual calibration
   documented below; this base sigma supplies its kernel/noise scale.
3. run_info.json/simulation_uncertainty records the law, scale, mean-position
   basis, estimation provenance, residual row/weekend counts/rounds, pooling,
   label policy, seed and sampling precision. A row is not an independent weekend.
   Derived retirement labels keep their existing training policy; item 5's
   published-position scoring remains unchanged.
4. Invalid simulation inputs fail clearly. Below 5,000 draws the terminal notes
   greater variation in shares/close-call estimates. The main table format and
   CLI count limits (100 to 1,000,000) remain unchanged. Zero-noise internal
   scenarios remain supported. Forecast samplers keep positive spread.

MEAN POSITION AND PERCENTAGES
Mean position is the analytic expectation under the selected score-noise model,
not a finite-sample average. Pole/first/top-three shares and close-call percentages
remain sampled fractions. At 25,000 draws the worst-case single-share Monte Carlo
standard error is .3162 percentage points. This measures counting precision under
this assumed model, NOT real-world forecast error or calibrated winning chance.
Increasing the draw count does not remove model/source uncertainty. Exact means
remove the numerical ordering fluctuation directly; antithetic/Sobol samplers
were also tested, but are not needed for exact mean positions.

EXPANDED METHODS AND RESEARCH
Beyond the original 96-setting review, the expanded work evaluates 160 study
configurations (including numerical controls and interval methods), 600 exact
winner-likelihood checks and 1,500 integration/seed comparisons. It includes:
  - analytic expected ranks and adaptive numerical winner probabilities;
    antithetic and scrambled-Sobol integration;
  - five-model calendar-block ensembles of the full native predictor, including
    active specialists; 400 unique model/control fits;
  - learned heteroscedastic errors, shrunk driver covariance, hierarchical
    posterior predictive spread, and Gaussian-process mean/covariance models;
  - event-block conformal and conformalized quantile intervals, assessed with
    coverage, width and interval score rather than winner-only metrics;
  - CDF/PIT, regularized multiclass and stage-conditional calibration;
  - pooled earlier GP/Sprint residual calibration, with numerical point order
    separated from genuine model changes, and earlier-event-only comparisons.
All past-session gap features are calculated within their own session. The audit
corrected a study-only grouping mismatch and reran affected experiments; those
pre-audit trials are excluded from final selection. Past raw/model inputs and
native feature matrices are preserved. No future labels enter calibration.

Representative primary sources:
  Gneiting/Raftery, proper scoring rules:
    https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jasa.pdf
  Kuleshov et al., regression calibration: https://arxiv.org/abs/1807.00263
  Lakshminarayanan et al., ensemble uncertainty: https://arxiv.org/abs/1612.01474

The ideas were adapted to the existing native-model pipeline; this does not
