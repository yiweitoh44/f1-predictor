F1 PREDICTOR: SETUP AND USE
Current baseline for predict_anytime.py

SETUP
Keep predict_anytime.py, session_influence.py, circuit_sections.py, grid_sources.py, tracks.csv
and requirements.txt together. This guide covers setup, scoring and validation.
Run only predict_anytime.py. The other Python files are imported helpers:
  session_influence.py  Session/history scores and qualifying/grid split.
  grid_sources.py       Published grids, source checks and pit-lane status.
  circuit_sections.py   Circuit categories and deferred section helpers.
Open the Git repository folder in VS Code and run commands there.
For a new environment, or after pulling the grid-sources update:
  python -m pip install -r requirements.txt
Check installed-package dependencies:
  python -m pip check
Fresh F1 timing downloads now require FastF1 3.9+ and an F1TV Access account
or higher, following Formula 1's October 2026 authentication change.
After installing requirements, sign in on YOUR laptop:
  python -m fastf1 auth f1tv --authenticate
Check sign-in status:
  python -m fastf1 auth f1tv --status
Then run the normal prediction command. Renew sign-in if it expires (typically
after four days). FastF1 stores its login token locally; do not share passwords
or tokens in chat or commit them to Git. Existing caches remain usable offline.
Zero-driver downloads are reported as access failures, rather than implying
the practice session is still running. A successful authenticated live download
still requires checking on the account holder's machine.
Upstream release: https://github.com/theOehrly/Fast-F1/releases/tag/v3.9.0
This checks dependencies, not whether Windows permits every compiled module.
The current script uses native XGBoost training, rather than XGBRegressor.
No OpenAI API key, LLM or GPU is required.

QUICK COMMANDS
Help (no race-data download):
  python predict_anytime.py --help
List events (internet required):
  python predict_anytime.py --year 2026 --list-races
Predict the Grand Prix:
  python predict_anytime.py --year 2026 --race Singapore --session race
Predict normal qualifying:
  python predict_anytime.py --year 2026 --race Singapore --session qualifying
Predict Sprint Qualifying, if scheduled:
  python predict_anytime.py --year 2026 --race Singapore --session sprint-qualifying
Predict the Sprint, if scheduled:
  python predict_anytime.py --year 2026 --race Singapore --session sprint

Replace Singapore with a location, country, event name or round number.
Quote names containing spaces. Ambiguous names are rejected.
Run before the selected session starts. Rerun after another earlier session
finishes and its data becomes available to update the prediction inputs.
Before current-weekend data exists, the script uses historical performance
and supplied circuit features. At least four usable training weekends in the
selected season are needed, with an eligible backtest of the requested type.

ALREADY-STARTED EVENTS
After the target's scheduled start, the script asks whether to continue.
Enter y or yes to use a cutoff one second before its scheduled start.
Enter or any other answer cancels.

Only earlier sessions completed before that cutoff are eligible.
The script lists the sessions it actually loaded. Live status is not
checked, and target-session laps or results are not prediction inputs.

You can also provide an explicit historical cutoff:
  python predict_anytime.py --year 2026 --race Singapore --session race --as-of "2026-10-11T11:59:00Z"
For another event, use its own verified pre-session cutoff.

Replay uses current published records, including later corrections,
rather than archived records of what was available at the original time.

ALL FLAGS
-h, --help           Show help and exit.
--year 2026          Season. Default: 2026.
--race Singapore     Event selector; required unless using --list-races.
--session race       race | qualifying | sprint | sprint-qualifying.
                     Default: race.
--list-races         List season events and exit.
--tracks tracks.csv  Circuit CSV; defaults to tracks.csv beside the script.
--roster roster.csv  Driver/team entries: driver,team; name is optional.
--grid grid.csv      Complete driver,grid CSV for a Race/Sprint, after its
                     corresponding qualifying data has loaded. Use PIT for pit-lane starts.
--grid-source auto   Prefer eligible published grids (default).
                     Use qualifying to explicitly retain Q/SQ order.
--refresh            Refresh FastF1 session caches and rebuild summaries.
--rebuild-summaries  Recalculate summaries while reusing raw FastF1 caches.
                     Add --offline to forbid downloads. If rebuilding fails,
                     retain an existing valid completed summary and report it.
--offline            Use cached FastF1 data only; make no network requests.
                     Cannot be combined with --refresh. Missing data stays missing.
--as-of UTC_TIME     Past replay cutoff before the target's scheduled start.
                     Example format: 2026-10-11T11:59:00Z. Z means UTC.
--simulations 25000  Sampled rankings. Default: 25000; range: 100 to 1000000.
--air-temp 30        Record air-temperature scenario, degrees Celsius.
--wet 0              Record weather scenario: 0 = dry; 1 = wet.
                     Both are diagnostic only in this version; neither changes
                     the score. Active weather effects belong to weather-context.

EXAMPLES
Refresh corrected results, before the target starts:
  python predict_anytime.py --year 2026 --race Singapore --session race --refresh
Record a wet, 30 C scenario (does not change this version's prediction):
  python predict_anytime.py --year 2026 --race Singapore --session race --air-temp 30 --wet 1
Apply a manually verified grid after qualifying:
  python predict_anytime.py --year 2026 --race Singapore --session race --grid grid.csv
For an already-started target, confirm the automatic pre-session replay prompt or supply a suitable --as-of cutoff.
Flags can be combined. Supplied relative paths use the terminal folder;
quote paths containing spaces. The default tracks.csv uses the script folder.
For a cached replay during network failures, add --offline to the command.
The season schedule must also be cached. This does not download missing data.

ROSTER AND GRID
Without --roster, use the latest loaded current-weekend roster, or the most
recent earlier competitive roster. Check replacements and FP reserve drivers.
After qualifying, published grids are selected automatically: dated FIA grid
first, then eligible Formula1.com/OpenF1 snapshots. Qualifying order is the
fallback. The terminal identifies the source. Source timing and conflicts are
explained below.
Use --grid-source qualifying to explicitly keep the Q/SQ-order assumption.
grid.csv must list every roster driver once, using abbreviations such as VER.
Use a unique grid slot, or PIT for a pit-lane starter; vacant slots are allowed.
Pit-lane starters are identified separately and share a back-of-field score;
exit order, delay and detailed recovery are not modelled.
Race/Sprint retain Q/SQ performance separately: the existing grid evidence
budget is shared equally between actual starting position and Q/SQ position.
This allows basic recovery estimates; it is not a lap-by-lap recovery model.

GRID SOURCES, TIMING AND MANUAL FILES
Source preference: complete manual --grid override, dated FIA documents,
eligible Formula1.com grid, eligible OpenF1 grid, then Q/SQ-order fallback.
Candidates must match the event/session and contain every entered driver once.
Malformed/incomplete grids are rejected rather than combined into a partial
guess. GP and Sprint grids are separate. Conflicts are recorded and the
higher-priority source wins. Recalled FIA documents are excluded. The latest
usable revision before cutoff is preferred; an older complete provisional can
be selected if a later document fails validation. Check the selected title.

FIA publication times use Europe/Paris, including its seasonal UTC offset,
although the website labels them CET all year. PDF issue times use the event's
local offset from the FastF1 schedule. The later time is used; disagreement
over two hours rejects the document. Year, session and date proximity are checked.
F1/OpenF1 records lack publication times, so retrieval time is the earliest
availability this application can establish. A grid first observed today is
not silently admitted into last week's replay. An ordinary prediction before
the target starts can use a grid fetched during that request; an explicit
historical cutoff cannot admit a later observation.

These are current copies of dated historical documents, not proof that the
same bytes were archived at their original issue time. Later corrections and
source availability remain limits of retrospective validation.

OpenF1 starting_grid records belong to the corresponding Q/SQ session key.
The adapter matches year, location, session name and scheduled time, then maps
numbers through that entry list. It does not query target results or running
order. OpenF1 pit-lane status is unknown; FIA's explicit pit-lane section and
recognised F1 notes can identify it. Unknown wording rejects that source.

F1Data/cache/grids holds raw responses and immutable parsed grid revisions.
Online responses refresh after five minutes; --refresh renews immediately.
--offline downloads nothing. Failed downloads can reuse cached responses only
under the same source identity and cutoff checks. Corrupt data is unavailable.

Manual grid.csv requires driver,grid and the whole entered field, for example:
  driver,grid
  VER,1
  LEC,2
  RUS,19
  ALO,PIT
This is an excerpt, not a complete usable file. Use unique numbered slots or
PIT; PL and PIT LANE are also accepted. Vacant slots are allowed. Optional
pit_lane true/false is accepted; true requires PIT, an empty slot or zero.
Optional known_utc values need an explicit UTC offset and must precede cutoff.
Without timestamps, the file is the user's assertion of the pre-session grid.
--grid is available only for Race/Sprint after corresponding qualifying loads.
--grid-source qualifying selects Q/SQ as the grid source; it does not restore
the older six-input race model or undo the adopted qualifying/grid score split.

Source references:
  https://www.fia.com/documents
  https://www.formula1.com/en/results/2026/races
  https://openf1.org/docs/#starting-grid

TRACKS AND WEATHER
tracks.csv is manual. location must match Location from --list-races exactly.
Recognised numeric columns:
  grid_stickiness        0..1 assumption; not a probability or fixed weight.
  length_km              Positive circuit length in km.
  longest_straight_km    Positive longest-straight length in km.
  slow_corner_fraction  0..1, using a consistent definition across circuits.
  high_speed_fraction   0..1, using a consistent definition across circuits.
  street                0..1; normally 1 for street and 0 for permanent.
basis is an explanatory note; the model does not use it.
Similar-track form requires at least two matching, nonmissing geometry/type
columns on the target and historical circuits. grid_stickiness does not count.
The current CSV enables manual category matching below; the separate numeric
geometry comparison needs these additional numeric fields.
Leave unknown values blank. Match the circuit layout used for the event.
Unsupported columns are ignored; adding them does not add model features.

Weather comes from completed sessions: median air/track temperatures and
whether rain was reported, using the latest available observations per field.
There is no forecast API. With no observations, weather stays missing unless
overridden. Weather and numeric geometry columns remain diagnostic fields;
only the evidence scores listed in HOW IT LEARNS below enter the model:
six for Q/SQ, seven for Race/Sprint including separate qualifying performance.
Manual weather scenarios do not change predictions in this version.

PACE AND TYRE ANALYSIS
Pace calculations exclude pit laps, inaccurate/deleted laps and laps without
an all-clear track status. Classified finishing positions remain available.

CIRCUIT PROFILES: MANUAL CATEGORIES
Keep circuit_sections.py beside predict_anytime.py.
Edit the five *_groups columns in tracks.csv. A | separates overlapping tags;
for example a circuit can have both slow technical and fast flowing corners.
All 26 listed circuits have at least one category, including the three added
for 2024-2025 coverage. Madrid uses the published layout description; its tyre
demand stays unknown. These are starting assumptions, not measured or official ratings.
profile_basis explains this; existing source URLs support only the previously
documented tags, not every added manual category. No tags are driver-specific.

Category comparison weights are GROUP_WEIGHTS in circuit_sections.py:
  Straights 25%, corners 30%, braking 15%, traction 15%, tyre demands 15%.
For each category, compare shared tags divided by all distinct tags across
both circuits, then multiply by its weight. Add the five contributions.
Blank categories contribute zero. This score measures configured similarity,
not confidence, accuracy or a driver's winning probability.

Earlier results at matching circuits are averaged separately for each driver
and their current team. Require at least two earlier matching weekends.
A Sprint and GP share one weekend's average; teammates share the team's
weekend average. The existing recency multiplier is 0.85 per elapsed round.
Only the previous four rounds are eligible now. Related-driver circuit form
has a 10% share within historical evidence when available; driver recent form
has 65% and current-team form 25%, redistributing missing components.
The 25/30/15/15/15 category weights still determine similarity, not final
winning chances. Team-related circuit form is exported as a diagnostic.

circuit_matches.csv lists prior tracks, their category contributions, raw
similarity and similarity times recency. historical_weight is zero outside
the four-round window; within_history_window explains eligibility. A positive
weight still requires two usable matching weekends for an individual driver.
run_info.json records the weights and window.
Weather remains based on session observations/manual overrides; a track's
usual climate is not substituted for the conditions on a particular weekend.

SECTION PACE IS DISABLED
Normal runs do not request car/position telemetry or calculate section pace.
Old section evidence in cached summaries is ignored by the feature builder.
All *_section_* columns remain excluded from every model fit. run_info.json
records section_pace_model_inputs=false and section_analysis.enabled=false.
The experimental helpers remain in circuit_sections.py for possible later
validation. Their presence does not enable them. Legacy section CSV filenames
are retained as empty exports for compatibility.

Previous telemetry investigation: a user-supplied Hungary sample reproduced
unrealistic section gaps. Positions were often stale, and comparisons between
drivers were not physically validated. No measured prediction improvement or
accuracy percentage has been established for this technique. Do not enable
it simply because a result looks plausible.

Summaries remain in F1Data/cache/anytime_v5_sections/<year>. Existing v4 and
raw FastF1 caches are retained. If no valid v5 summary exists, normal runs
reuse completed v4 summaries directly, with old section evidence removed in
memory. Original files are not rewritten; no manual conversion is needed.
Reusing a summary does not verify its raw timing cache or old telemetry.
No refresh is required for the category change:
category weights and profiles are applied when features are built.
Legacy summaries remain usable with the new extreme-gap guard. To apply the
new raw-lap filters once, with your laptop's existing raw cache, run:
  python predict_anytime.py --year 2026 --race Singapore --session race --offline --rebuild-summaries
For an already-started event, answer y to the usual replay question. This may
take time because it rebuilds earlier summaries too. It does not force raw
downloads or erase caches. Failed rebuilds retain prior valid summaries; check
the messages and pace_summary_version in run_info.json (2 means rebuilt).
If timing is unavailable, competitive classifications can be retained only
once the existing conservative session-completion check passes. Missing lap
data supplies no pace. run_info.json and the terminal report data coverage.

Practice short-run comparisons:
- Match compound, fresh/used status, tyre-age group and ten-minute window.
- Use tyres aged 1-5 laps.
- Take each driver's fastest lap within each matching group, then their
  median percentage gap across groups.
- Require at least two drivers per comparison group.

Longer-run comparisons:
- Require at least four consecutive valid laps within the same stint,
  compound and fresh/used status. Filtered-out laps break consecutive runs.
- Older tyres are allowed; there is no five-lap tyre-age limit.
- Match three-lap tyre-age groups: 1-3, 4-6, 7-9, and so on.
- Compare within ten-minute practice windows or five-lap race/Sprint windows.
- Use median lap times, requiring at least two laps per driver and two
  drivers within each comparison group.

Newly built summaries also omit laps more than 7% slower than that driver's
fastest valid lap on the same compound, and omit comparison groups whose
fastest/slowest driver paces differ by more than 7%. Removed laps break runs.
Before scoring, gaps outside 0..5% are omitted, never clipped to 0 or 5.
Each compound needs four eligible drivers with at least two matched samples.
Legacy summaries only have aggregate sample counts; per-compound support
cannot be established until rebuilt. These guards do not prove equal fuel or
programmes. Unmatched pace stays missing. No fixed tyre-time correction is
invented. These grouping thresholds are experimental assumptions.

The net stint pace trend measures whether lap times increase or decrease.
It does not isolate tyre deterioration from fuel burn or changing conditions.

Sprint evidence combines classified position (80%) and acceptable longer-run
pace (20%), redistributing missing parts. A known non-finisher or driver below
75% completed distance supplies no finishing-position pace evidence.
Finishing gap, completion, grid gains and disruption are also exported; they
are not separate model inputs.
Finishing gap is expressed as a percentage of the winner's race duration;
it is missing for retired/lapped drivers or unavailable timing.
It is result context, not a direct measurement of underlying race pace.

The model no longer uses raw practice/Sprint fastest-lap gaps as pace inputs.
Published grids are preferred for Race/Sprint, with Q/SQ order as fallback.
Qualifying performance also retains its separate share of the grid budget.
SQ order can inform later qualifying.
Raw qualifying gaps remain diagnostic rather than separate model inputs.

Matched-pace messages show how many drivers have usable comparisons.
Sprint short coverage is intentionally zero; Sprint uses longer-run pace.

Fuel correction, traffic filtering, isolated tyre deterioration and refinements
to the comparison groups are deferred. Tyre-aware matching does not guarantee
improved prediction accuracy.

Current displayed columns:
  Qualifying/SQ: Position, Driver, Team, Pole share.
  Race/Sprint: Position, Driver, Team, Mean position, Close call.
All four tables sort by mean simulated position, then model score, then driver
code for an exact tie. Position is the resulting 1..N ordering; mean position
is the average sampled rank. A predicted P1 can have a mean position of 3.23:
that driver has the lowest average in a simulation with substantial uncertainty.
Pole share is the percentage of simulations in which that driver finishes first.

A close call appears only on the lower driver's row, comparing that driver to
the one immediately above. For example, "↑ Hamilton beats Antonelli in 49.8%
of simulations" means HAMILTON finishes ahead in 49.8% of the existing draws.
The arrow becomes ^ on terminals that cannot encode it. No extra simulations
are drawn. The fixed 45%-55% display band marks near-even matchups throughout
the field; it is not a validated real-world confidence threshold. A lower mean
rank and a pairwise share slightly over 50% can coexist in a finite sample.
Mean positions print to two decimals, shares to one; CSVs retain full precision.

predictions.csv now contains predicted_position, driver (code), name, team,
and either mean_position/close_call (Race/Sprint) or pole_pct (Q/SQ).
Scripts reading the previous CSV need to update their column references.
simulation_details.csv retains first_pct (old win_pct or pole_pct), top3_pct
(old podium_pct), mean_position (old mean_simulated_position), score, and the
adjacent comparison driver/share. A blank top-row comparison is intentional.
Percentages are experimental simulation shares, not calibrated probabilities.

HOW IT LEARNS AND CURRENT LIMITS
Q and SQ share a training family; Race and Sprint share another.
Driver/team form uses the previous four rounds, with weight halved every three
rounds. One weekend gets one historical budget: GP/Q has three times the vote
of Sprint/SQ within it. Team form uses the driver's current team and averages
teammates within each historical session before smoothing.
Historical examples use session types available at the current input stage,
subject to each historical weekend's session order and actual availability.
Current-weekend results enter through session features, not historical form.
Labels are normalised finishing positions, including retirement-affected ones.

Up to eight eligible recent weekends of the requested type are backtested.
Fewer are shown when the season has fewer eligible tests (especially S/SQ).
Each test trains on earlier rounds; the printed fraction counts correct
first-place picks. Driver score errors from the latest four eligible tests
set the shared simulation noise; expanding the report does not change it.
The final model trains on all usable earlier examples, then samples rankings.
There is no lap-by-lap race simulation or additional retirement lottery.

Simple comparisons print HERE, beside the existing backtest report, before the
prediction table. Race/Sprint compares Model, Starting grid and Qualifying order.
Q/SQ compares Model with History only: the target's eventual Q/SQ results are
not an available pre-session baseline. History only uses the existing combined
driver/team/related-circuit historical score, without current-weekend evidence.

The comparison table uses the SAME eligible weekends and classified drivers for
every method. Missing baseline positions exclude that weekend from every method
in that table, while the usual model-only 5/8-style report still covers its full
latest eight eligible tests. CSVs record each method's eligibility and reason.
Historical grids come from FastF1's recorded grid field, available only at an
input stage with qualifying present. Zero, missing or duplicate slots are not
filled using qualifying. These historical records may include later revisions;
this is not a claim of original as-of grid snapshots. Qualifying order likewise
requires every evaluated driver's qualifying position. Before qualifying, the
race comparison can therefore be unavailable even if the model can predict.

Backtest model order remains raw-score order, which is expected mean-rank order
under the shared simulation noise. Its existing metrics and uncertainty remain
unchanged. Displayed means estimate that order from finite simulation draws;
nearly tied drivers can swap. Ranking error gives tied scores their average
occupied rank; driver code resolves ties for a single winner/top-three pick.
Validation only reports performance; it does not automatically tune weights.

The score is 85% explicit weighted evidence and 15% learned adjustment.
Competition gets more influence than practice when available. Missing sources
redistribute the weights; before current sessions exist, history supplies the
evidence. The policies below cover all four targets. Worsening an evidence
score cannot improve the learned prediction with other inputs fixed.
Published grids can include target penalties and pit-lane starts.
Race/Sprint use seven learned inputs, including separate Q/SQ performance;
Q/SQ use the original six. Grid and Q/SQ share the existing grid budget equally
when both are available. No circuit-dependent recovery weight is active.
No active weather forecast or quantified upgrade effect exists.
Simple comparisons are now included in the backtest display. There is no
probability calibration or automatic selection of the best-looking method.
Eight backtests alone do not establish reliable prediction accuracy.

SOURCE WEIGHTS AND MODEL INPUTS
Weights below are within the 85% evidence component, with all listed sources
available. Missing sources redistribute their weights per driver. These are
score assumptions, not percentages of winning probability.

Target               History  Grid/Q-SQ budget  Earlier Sprint  Earlier SQ  Practice
Grand Prix           20%      65%               10%             2.5%        2.5%
Sprint               20%      75%                0%             0%          5%
Qualifying           30%       0%               10%            50%         10%
Sprint Qualifying    85%       0%                0%             0%         15%

For Race/Sprint, split the grid budget equally between actual starting grid
and corresponding Q/SQ position when both are available: at full availability,
the GP's 65% becomes 32.5% each; Sprint's 75% becomes 37.5% each. Missing or
invalid Q/SQ performance retains the existing anchor. Equal Q/SQ and starting
positions leave that anchor unchanged. Q/SQ position is a performance proxy,
not a pure pace or recovery measurement. Mixed-stage lap-time gaps are not used.
The split is fixed; it does not use the circuit grid_stickiness value.
Before current sessions exist, history supplies the evidence component. On a
normal weekend, qualifying with only history/practice uses 75%/25% between them.

influence_weight_grid is the combined grid/Q-SQ budget. Its applied components
are influence_weight_starting_grid and influence_weight_grid_qualifying. They
sum to the combined budget; do not add the components to that budget again.

The six base model columns are influence_history, influence_grid,
influence_sprint, influence_qualifying, influence_practice and influence_anchor.
Race/Sprint add influence_grid_qualifying as a seventh column for Q/SQ performance.
The existing influence_qualifying column represents earlier SQ evidence; it is
not the separate current GP qualifying input. Missing learned inputs use history.
If all historical evidence is absent, its explicit neutral fallback is 0.5.
Normalised scores are smaller for better performance. Native model predictions
are bounded to 0..1 and monotone in each active input. This does not guarantee
the same rank when other drivers, available sources or training examples change.

Training uses all usable earlier rounds in the selected season. Example weights
halve every six rounds and are divided by weekend row counts, so Sprint weekends
do not get twice the training weight. Current form still uses the four-round
window described above. History is updated only after a weekend's feature rows
are built; same-weekend evidence enters through explicitly eligible sessions.
Historical grids are used only at a stage where corresponding Q/SQ is available.
Historical pit-lane records with grid=0 retain the existing qualifying fallback.

model.json stores only the native 15% component. To reproduce the full score,
use (1-learned_share)*influence_anchor + learned_share*clip(native_prediction,0,1).
run_info.json records that formula, blend and exact model_features;
influence_policy.json and session_influence.csv record policy and applied weights.
A cache stores session observations, not a pretrained model or prior predictions.
Every run retrains; missing history or timing downloads can still prevent a run.
